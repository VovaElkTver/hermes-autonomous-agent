# Аудит раунда 3: embedding-конвейер, демонтаж крона, долг

**ВЕРДИКТ: GO-WITH-CONDITIONS** — поправки владельца реализуемы, но в формулировке агента три ловушки: чисто-семантическая привязка подзадач (q4), запуск классификатора без shadow-периода, и watchdog, который умрёт вместе с хостом.

---

## A) Embedding-классификатор

### Врезки (три точки, разного права)

1. **Inbound-gate перед сменой состояния W1/W4** — единственная точка, где классификатор *мутирует* состояние. Верdict-голова: {ПРИНЯТЬ, ОТКЛОНИТЬ, УТОЧНИТЬ, МЕТА, НЕ_К_ФОРКУ}.
2. **Attribution при создании подзадачи (q4)** — в момент создания фиксируется структурная запись `(fork_key, снимок темы, вектор)`. Это не парсер и не реестр для человека — это внутренний ключ, что владельцем разрешено явно.
3. **Outbound-привязка** (реплики main к форку для топологии) — read-only голова, переходов состояний не порождает. Если её дать право мутировать — двойной вход в машину состояний, рассинхрон.

Геометрия: embedding не голой реплики, а конкатенации `[снимок темы форка + последние N реплик + реплика]`. Голая реплика на коротких «ок», «давай так» — основной источник false-accept, потому что антецедент местоимения живёт в контексте, а не в реплике.

### Порог неоднозначности

Двухбарьерный: лучший класс `s1`, второй `s2`. Переход только при `s1 ≥ τ_abs` И `s1 − s2 ≥ δ`; иначе УТОЧНИТЬ. Асимметрия обязательна: **τ(ПРИНЯТЬ) > τ(ОТКЛОНИТЬ)** — цена false-accept это исполненная чужая работа и merge-back не туда, цена false-clarify — секунды владельца. Числа τ/дельта — плейсхолдеры до калибровки, в конфиг, не в код. [МЕЛКО]

### Калибровка без id-реестра

- Bootstrap: слабые метки из топологии — форк влился ⇒ предшествующий вердикт = ПРИНЯТЬ; закрыт без слияния ⇒ ОТКЛОНИТЬ; реплика-вопрос владельца ⇒ УТОЧНИТЬ. Ручная верификация 50–100 штук.
- Пополнение: каждое ручное исправление владельца = новая размеченная точка. Пересборка порогов при override-rate выше порога за скользящее окно.
- Метка уровня форка, не реплики — сегментация диалога на вердикт-моменты сама ошибочна; слабые метки годятся только как старт, не как истина.

### Деградация

Embedder недоступен: реплика в **HOLD-очередь**, состояние остаётся W1, взводится kernel-таймер старения очереди (тот же механизм flood-redelivery). Одно сообщение владельцу о деградации, не на каждую реплику. На восстановление: replay по порядку, dedup по хэшу, позднейшая вербальная дубликат-реплика владельца побеждает. Классификация не блокирует доставку сообщений — только переход состояния.

### Находки A

- **[КРИТИЧНО]** Привязка q4 *чистым* embedding'ом как источником истины: соседние подзадачи одного этапа семантически ближе друг к другу, чем к чужим этапам; ближайший сосед ≠ происхождение. Происхождение — графовая структура, её нельзя вывести из похожести. Последствие ошибки: работа исполняется под чужим W-состоянием и вливается не в ту ветку. Embedding — резолвер сирот и поиск; ключ в момент создания — истина.
- **[СЕРЬЁЗНО]** Запуск без shadow-режима: первые недели пороги не откалиброваны → поток ложных УТОЧНИТЬ → владелец теряет доверие → откат на лексику. Минимум 2 недели «решает, но только логирует».
- **[СЕРЬЁЗНО]** Петля самообучения: дообучение на собственных решениях без внешних меток самоподтверждается. Метка — только override владельца или финальная топология.
- **[СРЕДНЕ]** Консервативная деградация «никогда не принято без семантики» при затяжном простое embedder = накопление W1-форков → массовый залп T1/T2. Деградация должна быть спроектирована вместе с W3-таймерами, иначе они противоречат друг другу.
- **[СРЕДНЕ]** Задержанная обратная связь (метка через дни) — окно дрейфа качества; опережающий индикатор: средний косинус и доля пограничных решений.
- **[СРЕДНЕ]** Latency в горячем пути: кэш по хэшу контента, батчинг, бюджет 1–2 с, таймаут = HOLD.

## B) Карта событий вместо крона

| Функция тика | Замена |
|---|---|
| Посмертные хвосты | boot + auto-resume (залито, 30dfa61344) |
| Зависшие форки | T1/T2 в ядре, прецедент flood-redelivery; взводятся самими переходами, персистятся, одиночный выстрел, джиттер |
| Незакоммиченное/незапушенное | события VCS-хуков (post-commit/push → шина ядра); таймер «грязное дерево» взводится при агентской мутации, разряжается коммитом; скоуп — только агентские пути, иначе тревога на правки владельца |
| Висящие внешние ожидания | парный дедлайн-таймер на каждое ожидание; инвариант API «нет ожидания без ttl» |
| Housekeeping | внутренние таймеры ядра (тот же поток, не сессии) |

Дыры, которые события не закроют **по построению**:

- **[СЕРЬЁЗНО]** Краш между действием и записью журнала — резюмить нечего, события не стреляют. Нужен write-ahead журнал намерений: «нет действия без журнальной записи до исполнения». Без этого auto-resume возобновляет только то, что успело записаться.
- **[СРЕДНЕ]** Crash-loop → шторм resume при каждом буте. Нужен boot-dedup/бэкофф.

Ответ на вопрос «ядро мертво — кто бьёт тревогу»: никто изнутри, из трупа события не приходят. Три кольца:

1. Таймеры ядра (в потоке) — покрывают всё, пока ядро живо.
2. Same-host dead-man: тупой процесс (без LLM, без сессий, без промптов — чтобы не гнил вместе с ними), следит за heartbeat-файлом; по устареванию — рестарт + эскалация; rate-limit рестартов.
3. **Off-host liveness** (внешний пингер) — единственное, что кричит при смерти хоста целиком. Канал — человеку.

- **[КРИТИЧНО, если пропустить]** Heartbeat должен эмититься из хвоста **главного цикла** ядра, не из бокового потока и не из тика: иначе wedge при живом процессе выглядит как жизнь, и кольцо 2 молчит.
- **[СЕРЬЁЗНО]** Если сегодня де-факто доказательство живости эмитит тик — демонтаж тика молча ломает кольцо 2. Разделить до удаления.

## C) Вердикт по формулировке долга

По духу — верна, с двумя ужесточениями:

1. **«При внедрении W0–W4» — не дата.** Заменить измеримым предикатом: (а) каждая функция тика имеет именованную замену-событие в проде; (б) N дней shadow-сравнения — тик-детектор логирует, что сделал бы, расхождений ноль; (в) учебный kill-drill обоих колец watchdog. Иначе «временный костыль» — вечный.
2. **Порядок демонтажа:** события → тик переводится в режим «только детектор, работ не начинает» → перекрытие → удаление. Немедленное удаление с дырой — против интереса владельца: его жалоба на cron — это *потеря контекста у продолжателя*, а не разрыв непрерывности работ. Запрет сосуществования относится к роли «продолжатель», не к секундам таймера — прецедент владельца (flood-redelivery) это подтверждает.

- **[СРЕДНЕ]** «Только watchdog, не продолжатель» ретроактивно меняет поведение живого компонента — зафиксировать коммитом/правилом в репозитории, а не памятью разговора.
- **[СРЕДНЕ]** Freeze scope: на переходный период тику запрещено обрастать функциями, иначе демонтаж никогда не наступит.

## Что упустил автор

- **Escape hatch**: явная фраза-байпас владельца мимо классификатора. Без неё консервативная деградация — ловушка, построенная руками владельца.
- **Cap петли уточнений**: УТОЧНИТЬ → ответ тоже неоднозначен → УТОЧНИТЬ… Максимум одно авто-уточнение, дальше дамп контекста.
- **Идемпотентность replay** после простоя embedder — повторный вердикт не должен дважды сдвинуть состояние.
- **Скрытая цена калибровки платит владельцу**: 50–100 ручных разметок. Получить согласие до старта, не после.
- **Снимок темы форка в момент создания** подзадачи — тема дрейфует, поздний embedding свяжет с уже другой формулировкой.
- **Feature flags на каждую врезку отдельно** — откат точки, а не всего конвейера.
- **Метрики с первого дня**: доля УТОЧНИТЬ, override-rate, глубина HOLD-очереди, SLA embedder, рестарты watchdog. Без них калибровка вслепую.

---

**GO-WITH-CONDITIONS. Top-3 условий:**
1. Shadow-режим ≥ 2 недель и асимметричные пороги (ПРИНЯТЬ строже) до любого живого действия классификатора.
2. q4: структурный ключ в момент создания — источник истины; embedding — только резолвер и поиск. Чисто-семантическая привязка = NO-GO.
3. Watchdog: тупой, с heartbeat из главного цикла ядра, плюс off-host кольцо; одновременно — write-ahead журнал намерений, иначе auto-resume возобновляет не всё.
