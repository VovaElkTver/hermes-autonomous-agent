ВЕРДИКТ: СМЕЩЁН к управляемому workflow с человеческой арбитражной точкой — механизмы автономности (fork, предикаты, origin-реестр) наращиваются быстрее, чем сокращаются точки обязательного участия Вл; план строит платформу для автономии, но почти каждый выход из этапа упирается в нового человека-в-цикле.

## 1. Автономный агент или workflow с арбитражем

Тянут к автономии:
- **Join-протокол 01.11** (п.6 швов): конфликт веток разрешает агент, третье решение допустимо, к человеку — только по полномочиям. Единственное место, где смысловое решение явно возвращено агенту.
- **Фикс holds_admission** («Хвост автономности»): убран класс вечного вето на boot auto-resume — минус ручные пинки «почему после рестарта ничего не делаешь».
- **Запрет «не-я»** (ПРАВИЛО ПОТОКА): продолжение потока всегда имеет автора-агента — подотчётность без внешнего арбитража.

Тянут к workflow:
- [СЕРЬЁЗНО] **stage001 п.6**: три узла = три отдельных «иди» на один артефакт. Человек встроен в цикл развёртывания как обязательная ступень.
- [СЕРЬЁЗНО] **Реестр «ЖДЁТ ПРИЁМКИ»**: вердикт только у Вл. Сейчас 6 открытых / 0 закрытых — собственная метрика баланса («открытые не должны расти быстрее закрытых») провалена в первый же день замера. Правило «приёмка не заслон» не отменяет: непринятое блокирует зависимое (деплой #69 ждёт с 29.10, stage001 строился поверх недеплоенного — паттерн уже реализован).
- [СРЕДНЕ] **Shadow-классификатор**: право существенного действия — после «явного решения человека», срок — календарные 2 недели, к качеству shadow-данных не привязан. Две недели агент неавтономен по построению, независимо от данных.
- [СРЕДНЕ] **Метрика «доля работ над самим агентом»**: весь текущий план — работы над самим агентом. По этой метке этап провален по построению; скрытое допущение — конверсия платформенной работы в пользовательский результат, нигде не измеряемая.

## 2. Перекосы ограничений

Перекрытие сверх технической необходимости:
- [СРЕДНЕ] Деплой-гейт ×3 (п.6). Целостность требует один зелёный артефакт + порядок раскатки + откат; три «иди» — ритуал. Цена уже оплачена: дрейф версий флота породил атрибуционную ошибку «Rtx5090 = отдельная машина» (ОБНОВЛЕНИЕ 31.10-2) — расследование по ложной гипотезе.
- [МЕЛКО] Cap авто-уточнений = 1: константа без связи с целостностью; второе тривиальное уточнение получает дамп контекста.

Недостаток ограничений:
- [КРИТИЧНО] **Dedup при redelivery.** Вводится boot-redelivery прерванного тёрна; предикат читает токены решения из ленты; защёлка `UPDATE…WHERE status='active'` жила в удалённом плагине и для будущих механизмов не зафиксирована как инвариант. Доктрина объявляет «не является ли доставка повторная» условием ядра — мероприятия в плане нет. Redelivery × повторное чтение того же «записать» = двойное исполнение, молча, на данных пользователя. Это прямой удар по цели «восстановление без потери принятой работы».
- [СЕРЬЁЗНО] **«Расхождение с лентой = инцидент» — норма без детектора.** Пункта-реконсиляции нет; аксиома Уточнения 01.11 неисполняема до первого случайного ручного обнаружения.
- [СЕРЬЁЗНО] **Разрыв тред-lineage** (косяк p.5): три меры «на выбор», выбор не сделан. Режим отказа воспроизводим: `/resume` из комнаты не видит живую ветку своей же тред-линии — работа есть, недоступна.
- [СРЕДНЕ] **Полнота ленты принимается как данность.** Лента собирается адаптером с пересборкой событий (debounce, media-fusion, reply-fetch — тот же шов, где жил provenance-баг). Потеря события адаптером = тихая неполнота единственного свидетельства. Мониторинга полноты (ingress-counter ↔ лента) нет.
- [СРЕДНЕ] **CLI-контур**: аксиома требует history, v7 держал диалог в RAM; мероприятие записано, статус после удаления плагина неопределён — для CLI-сессий свидетельство может не существовать.
- [СРЕДНЕ] **«Событие, не таймер» реализовано таймерами**: 1 Гц в замысле, 5 с счётчик плагина, 30 с тикер гейтвея — три гранулярности, латентный бюджет предиката не определён.

## 3. Живучесть документа

Порог дезинформации уже взят:
- [СЕРЬЁЗНО] Объект stage000 удалён (`91b692e9a3`), но условия критика 0–2 и императивы stage000 п.1–5 стоят в повелительном наклонении без пометки на месте. Агент, исполняющий документ буквально, рискует воскресить карточный слой, запрещённый дважды.
- [СЕРЬЁЗНО] Актуальность факта по удалённому плагину устанавливается цепочкой из 3+ переходов (v7 → ОБНОВЛЕНИЕ 30.10 → stage001 п.4 → «План завершения» п.1/п.4). Это и есть порог: **>2 обновления на факт — документ начинает врать**. Таких фактов уже минимум три (удалённый плагин, JoinPacket, диагноз п.6 от 10:01).
- [СРЕДНЕ] Двойная книга: удаление плагина одновременно «прямое указание Вл» (исполнено) и строка «awaiting: подтверждение Вл». Не определено, что является состоянием — факт или приёмка.
- [СРЕДНЕ] Вынос истории в journal/ отложен без триггера («когда объём начнёт конкурировать» — неизмеримо, значит никогда). Нужен операциональный: секция с >1 ревизией инварианта переезжает целиком.
- [СРЕДНЕ] ПРАВИЛО ПОТОКА без позитивного определения идентичности потока: каждый комментарий адресован неопределённому «тому же потоку»; стоимость комментариев линейна по событиям, семантика — суспендена до формулировки Вл. Правило можно будет задним числом перечитать — и прошлые комментарии потеряют смысл.

## 4. Баланс по критерию Вл

Структурно улучшает (auto-resume без пинка, resume-конфликты без арбитража, join без внешней точки), в наблюдаемом окне — **ухудшает**: очередь приёмок растёт, деплой-гейты умножены, shadow-заморозка снимает участие по календарю, а не по качеству. Замеров метрик не было ни одного (автор признаёт).

Топ-3 перегруженных:
1. **stage001 п.6 (флот)** — максимум касаний Вл на единицу проверенного изменения; туда же прицеплены разбор win-autostash и E2EE-warning.
2. **Реестр «ЖДЁТ ПРИЁМКИ»** — FIFO на одного человека без SLA, батчей или делегированных критериев по типам пунктов; динамика 6/0 на старте.
3. **Dual-run autonomy-tick ↔ W0–W4** — костыль обязан жить ≥2 недели shadow + kill-drill + демонтаж, freeze-scope запрещает ему обрастать функциями, но до W3 он один обслуживает восстановление. Долгоживущий костыль в критической роли — худший класс компонента.

**ИТОГ: GO-WITH-CONDITIONS.**

Top-3 условий:
1. **Идемпотентность исполнения как инвариант ядра**: durable-ключ (intent-id, ветка, сообщение-решение) до dispatch, проверка при каждом исполнении включая boot-redelivery; тест двойной доставки — в сетку п.5.
2. **Детектор реконсиляции лента↔внутренние записи** (регулярный diff, счётчик расхождений в events-jsonl) + монитор полноты ленты (ingress-counter ↔ лента). Без этого аксиома «улики обязаны сходиться» — декларация.
3. **Сжатие арбитражных точек**: один «иди» на проверенный артефакт для всего флота (порядок + откат внутри процедуры, не три вердикта); реестру приёмки — SLA/пакетная приёмка; в документе — правило supersede («отменено X» на месте текста), иначе агент будет строить по устаревшей карте.
