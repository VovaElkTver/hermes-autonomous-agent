# Deferred interrupts — регистр отложенных прерываний агента

Status: CURRENT (design v0)
Line: autonomous-agent / controller
Parents: docs/design/literal-pass.md (общая механика отказа-с-именем-метода), docs/controller.md

## Постановка

Сегодня событийные ожидания («переспросить после X», «продолжить, когда Y») либо
превращаются в таймеры (неудачный шедулинг: событийный маркер ≠ абсолютное
время), либо забываются. Нужен внутри-агентный аналог ISR: обработчик,
пробуждаемый СМЕНАМИ СОСТОЯНИЯ, а не часами.

## Модель MCU ↔ Hermes

| MCU | Hermes |
|---|---|
| main loop | цикл ходов (turn loop) |
| ISR / векторная таблица | хук pre/post turn + реестр ожиданий |
| flag register | записи в state.db (ctl_event, ctl_task.state, строки rooms) |
| аппаратный таймер | cron no_agent (только для ЧИСТО временных ожиданий) |
| немаскируемое прерывание | preempt между tool-вызовами (не посреди генерации) |

Фундаментальное отличие: у агента нет тиков между ходами — процесс может не
жить (epoch). Поэтому РЕЕСТР живёт в state.db (переживает рестарт), а обработчик
выполняется, когда ход случается по любой причине. Часовой счётчик внутри
модели невозможен в принципе; счётчик событий (ходы, tool-вызовы, перемены
состояния) — Возможен полностью.

## Сущность: ожидание (watch)

```
watch_id, owner_scope, created_at, epoch
when:   предикат — один из:
        state_changed {task_id, to_state}          (SQL-условие по state.db)
        file_appears  {path, glob}
        room_keyword  {room, pattern}
        counter       {name, op: ">=", value}      (счётчик событий, не время)
then:   inject {text, where: next_turn_context}   | wake {profile}
once:   true|false (repeat)
ttl:    опционально — ЧИСТО временная страховка, не основной способ
status: armed | fired | cancelled | expired
```

API (плагином, рядом с guardrails):
- `watch_arm(when, then, once=True)` — явная постановка (человек или агент);
- ядро на post-turn hook проходит по armed-записям, дёргает дешёвые детекторы
  (тот же класс, что monitor_script у cron), при истинности — инжект `<DEFERRED
  INTERRUPT watch_id=… text=…>` в контекст СЛЕДУЮЩЕГО хода и переводит в fired.

## Дисциплина (главный пункт, а не механика)

**Прежде чем уснуть с незакрытым хвостом, агент обязан задать себе вопрос
владельца: «могу ли я сделать что-то прямо сейчас без человека?»** — и затем:
- можно сделать → делает в этом же ходе (не записывая watch);
- ждёт СОБЫТИЯ → `watch_arm` (не таймер!);
- ждёт ЧЕЛОВЕКА → watch на ответ/команду в комнате, не «напомню через N часов»;
- ждёт ВРЕМЕНИ (окно GPU, ночной прогон) → единственный случай для cron.

Этот порядок и есть ответ на инциденты 18.10: pr47-reshow (событие→таймер,
удалено), pump-простаивание (идея работала, тика не было — теперь tick есть,
watch поверх него даст событийную доставку).

## Границы v0

- только спека; пилот-хук (plugin ~50 строк, post-turn) — отдельной задачей
  после приёмки;
- детекторы — из закрытого списка (никакого eval произвольного кода);
- максимум активных watch на скоуп (антизахламление, как с cron);
- fired-инжект обязан называть watch_id — история прерываний = ctl_event.
