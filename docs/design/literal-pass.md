# Literal pass — `/gen off`: харнесс-обходимое дерево данных

Status: CURRENT (design, v0)
Line: autonomous-agent / controller
Parent spec: docs/controller.md
Prototype: scripts/literal_pass.py

## Проблема (наблюдение vovak 18.10)

Задача «проанализировать по смыслу каждый документ в папке» (itog-колонка в
одной таблице F, в другой K; итог в строке 15, в другой 12) решается агентом
генерацией generic-скрипта, который портит файлы (openpyxl/pandas съедают
формулы, сводные, стили; паттерн с одного «успешного» документа тиражируется
на всё дерево). Задача ставилась «точно, не быстро» — но нигде это не было
машинно-проверяемым свойством задачи, и приор модели (растерировать паттерн N
раз) победил.

## Принцип

Не послушания просить — убрать возможность непослушания. Итерации
**буквальны**: цикл принадлежит харнессу, модель за одну итерацию видит ровно
одну вершину дерева.

`/gen off` = режим, в котором:

1. **Инвентарь строит харнесс.** Детерминированный обход (`walk`, sorted,
   include-маска) даёт список вершин; модель списка не видит целиком, она
   получает текущую вершину и счётчик `k of N`.
2. **Контекст итерации чист или бюджетирован.** Промпт итерации: задача +
   ПУТЬ + «документ k из N». Прошлые вершины доступны только как данные
   журнала, не как контекст разговора — иначе к 30-й итерации компрессия
   начинает резать углы.
3. **Единственный канал записи — commit(вершина, изменение).** Прямые writes
   в дерево данных guardrail-ом режутся. commit: (а) пишет в staging-копию;
   (б) структурно сверяет копию с оригиналом — всё, что не покрывается
   манифестом итерации, обязано совпадать (значения ячеек, presence формул,
   list sheet'ов, имена определяющих областей); (в) при рассогласовании —
   автоматический откат и отказ с **именем метода**.
4. **Журнал = sidecar, не контекст.** `.pass/journal.jsonl`: на вершину —
   манифест (`{"file","итог":"F15","доказательство":"шапка «Итого к
   оплате»"}`), diff-хеш, статус. Приёмка задачи = reconcile по журналу,
   а не «готово» модели.

## Триада штрафа («не отменять вознаграждение, а указать, что метод штрафуется»)

Скалярной награды в рантайме LLM-агента нет; «вознаграждение» = что написано
в контексте в момент выбора метода. Штраф должен быть называемым, оплаченным,
переживающим сессию:

1. **Сессия:** guardrail-отказ называет МЕТОД («generic batch-скрипт
   отвергнут как метод per-item задачи; штраф, работай по одной вершине»),
   не только запрет. Модель обновляет оценку метода, а не обходит параметр.
2. **Приёмка:** reconcile отклоняет «готово» с ценой: «принято 12/40,
   метод стоил 28 переделок». Переделка после собственного «готово» —
   сигнал, на который веса реально реагируют в контексте.
3. **Память:** каждое срабатывание — урок в скилл/память по формату
   evidence-gated lessons (harness²): `{метод, класс задач, вердикт=штраф,
   доказательства N}`; retrieval подтягивает его в момент следующего выбора
   метода того же класса.

## Интеграция (не новая подсистема)

* классификатор `per-item vs batch` — поле контракта (`iteration: literal`),
  решает Approver/менеджер при постановке, не исполнитель;
* движение курса — тот же pump (ctl_step на вершину, checkpoint), либо
  локальный цикл `literal_pass.py` в интерактивной сессии;
* канал записи — расширение `fork-guardrails` (плагин-хук write, уже
  существует) + structural-verifier по типу файла (xlsx/csv/pdf…);
* `/gen off|on` — slash-команда режима (тогда же: desktop slash-registry,
  docs row, locale keys — см. CI-ratchet convention).

## Прототип v0 (scripts/literal_pass.py)

Механика харнесса без LLM: инвентарь, курсор, `commit` c structural
verification и откатом, journal, reconcile-отчёт. Per-item анализ подключается
колбэком (в проде — делегат с чистым контекстом). Проверяется на синтетических
xlsx с разными layout'ами итога.

## Что показал прототип (эмпирика, не вера)

- Synthetic-тесты openpyxl 3.1.5: круговые диаграммы/изображения/именованные диапазоны при
  простом reload+save НЕ теряются — миф о «openpyxl всё портит» в базовых кейсах не подтвердился.
- Значит реальный класс поломок из практики — **семантический**: generic-паттерн, снятый с
  одного документа, пишет в чужие ячейки (колонка F вместо K, строка 15 вместо 12) и
  перезаписывает файл целиком. Именно это ловит верификатор v0 (все ячейки вне манифеста
  идентичны значению и data_type; списки листов; имена частей zip-пакета, белый список
  безопасных потерь calcChain).
- Байтовая верность файлов, созданных Excel'ем (сводные таблицы, форматирование,
  целочисленные идентификаторы shared-строк), v0 НЕ проверяется — на то и fail-closed
  реестр типов: для типа нет верификатора — записи нет.
- Штраф в отказе назван по имени метода — текст отказа является сигналом для модели,
  см. триаду.
