# Maintenance epoch — проект (D из разбора 09.11, го Вл)

Статус: проект на утверждение. Код-предпосылка уже в ветке `elk/controller-wake-budget`
(бюджет-гейт стал настоящим: `limit_value` пишется контрактом и CLI).

## Проблема
Самовопрос («что ещё полезного сделать на idle-бите») упирается в собственный
запрет форка: `no model text can approve` (disposition §45, acceptance Q2/Q5).
Без разрешения агент может породить can-do задачу, но материализовать и
выполнить её себе не вправе — draft висит до человеческого «иди task-x».

## Предложение: per-scope maintenance epoch
Человек ОДИН раз выдаёт scope автономия-грант класса maintenance:

```
ctl scope-grant <workdir> maintenance --budget-steps N --budget-tokens M [--ttl-days K]
```

Внутри гранта на idle-бите (eligible пусто, никто в needs_human/paused не ждёт):
1. генератор кандидатов берёт материалы из ctl_todo (draft-намерения) + детектора
   (устаревшие journal, открытые followup-review, red-гейты) — никаких выдуманных целей;
2. задача класса maintenance (read-only/инспекция/отчёт; allow-list kind'ов
   `inspect`, `report`, `audit` — не пишут в прод) материализуется с контрактом,
   где `agreed_by="maintenance-epoch:<grant_id>"`;
3. self-agree разрешён ТОЛЬКО maintenance-классу и ТОЛЬКО внутри гранта;
   всё остальное выставляется человеку в очередь «иди» (штатный путь).

## Почему это не ломает доктрины
- `authority granted, not assumed`: грант даёт человек, текст модели по-прежнему
  не согласует — согласует запись гранта с бюджетом.
- Бюджет — не обещание, а код: `limit_value` теперь пишется (коммит 09.11),
  `budget_exhausted` реально блокирует, перерасход → blocked + alert.
- 1 Гц не трогается: idle-ветка считается теми же счётчиками поверх бита;
  wake-шв (файл-колокольчик) уже даёт реакцию на грант-мутации без рестарта.
