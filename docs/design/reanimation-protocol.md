# Протокол реанимации (fleet) — как работать с живым гейтвеем

Мёртвый кейс, породивший протокол (27.10): агент из живого терна сделал `checkout` на
`90c1ae8b7c` + отложенный рестарт гейтвея таймером (`sleep 15`). Гейтвей не поднялся.
Обещание «после онлайна сверю MainPID» не могло исполниться никогда: терн умирает вместе
с гейтвеем, свидетеля не остаётся. Труп висел до ручного вмешательства владельца.

Протокол — операционная надстройка над `docs/design/safe-mode-rescue.md` (та там, где ядро
и kit-руки; здесь — дисциплина того, кто их использует).

## Правила

1. **Билет на выход — до действия.** Перед любой операцией над живым узлом:
   `git rev-parse HEAD` → целевая SHA возврата записывается в `DEPLOY-NOTE.md` (корень репо).
   Рабочее дерево чистое: всё закоммичено или `git stash push -m "<что/зачем>"`. Локальный
   undeclared diff в рантайме живого узла запрещён — прецедент: `start_writer` без
   `thread.start()` отключил housekeeping (а с ним и respawn тикера #111010) на production,
   и об этом не знал никто, кроме diff'а.
2. **Deploy = коммит на fleet-ветке; откат = `switch_release`** (атомарная перелинковка
   `~/hermes-live`). Git-команд в аварийном контуре — ноль (инвариант 6 safe-mode-rescue).
3. **Агент не планировали себе рестарт из своего терна.** `sleep N && restart` из живого
   терна — сиротская смерть. Исполнитель смерти — внешний: `scripts/hard_reboot.sh`
   (detached), `/reset-safe` (следующий boot в SAFE-identичности), рука владельца
   (`systemctl --user restart <unit>`) или rescue.
4. **Проверку делает тот, кто пережил рестарт.** `python -m hermes_rescue run-once --report`
   (inspect → decide → kit → observe 120 с → рапорт). Обещание мёртвого агента «потом сверю»
   проверкой не считается и не принимается.
5. **Торжество над трупом.** Новая сессия, поднявшаяся на подозрительном узле: читает
   `DEPLOY-NOTE.md` и секцию «Fleet: before touching a live gateway» в `AGENTS.md`, сверяет
   MainPID юнита с `~/.hermes*/gateway.pid`, гоняет rescue `run-once`, рапортует в owner-room,
   потом снимает заметку.

## Формат DEPLOY-NOTE.md (корень репо, жить не должен)

```
deploy: <что и зачем, одна строка>
from:   <SHA возврата>
to:     <SHA/ветка целевая>
risk:   <что может не подняться и почему>
who:    <агент/ветка, оставивший заметку>
```

Заметка существует между «запланировали» и «проверено живо». Если заметка есть, а гейтвей
нездоров — это инструкция, а не артефакт; если гейтвей здоров — удалить тем же коммитом,
которым закрываешь деплой.

## Что это не меняет

- Rescue-ядро, SAFE-флаг, kit-операции — по `safe-mode-rescue.md`, здесь только порядок рук.
- Для мирных изменений (не трогает boot-путь живого гейтвея) достаточно правил 1 и 4.
