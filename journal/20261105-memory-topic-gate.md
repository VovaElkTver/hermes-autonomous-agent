# memory.topic_gate — гейт тематической памяти (05.11)

**ТЗ:** `docs/TZ/prompt-for-rtx5090-memory-topic-gate.md` v0.1 · мандат Вл «го» в DM @rtx5090.
**Ветка:** `elk/topic-gate` от more-mem-layer @ `9b3ed7c9fb`. Деплой не активирован — флаг
`memory.topic_gate` по умолчанию false, живой шлюз продолжает работать старым кодом до приёмки.

## Исполнено

- **Реестр и матчер** — `tools/memory_topic_gate.py`: YAML-реестр тем, живое перечитывание
  по mtime (школа need2write), кэш валидный пока файл не менялся. Конвенция match: `re:` —
  регэксп, есть `* ? [` — glob с обёрткой, иначе подстрока. Первая совпавшая тема выигрывает.
  Любая ошибка чтения/парсинга = fail-open («тем нет») + warning; гейт никогда не ломает запись.
- **Единая точка принуждения** — `tools/memory_tool_store.py::MemoryStore`: один перехват на
  публичных методах (add / replace / remove / patch / apply_batch), куда сходятся ВСЕ писатели
  builtin-памяти (проверено grep'ом: slash-команды и консолидация идут через те же методы;
  curator/learning_graph только читают). Гейт действует только для `target="memory"`.
- **add**: совпал реестр → запись целиком в append-file темы (атомарно, тот же §-формат),
  в MEMORY.md идемпотентная строка-указатель (точное совпадение текста), ответ сообщает
  «Записано в тему 'X' → path» (§5.3). Не совпал → штатная ветка байт-в-байт.
- **replace/remove/patch**: old_text матчит реестр → операция идёт в store темы; промах там —
  честная ошибка «entry belongs to topic X … Nothing was written»; в MEMORY.md тематическая
  операция не падает никогда.
- **Батчи**: операция, роутящаяся в тему, внутри батча = отказ ДО любых записей (батч не может
  быть атомарным по двум файлам), в ответе список op#→тема и просьба разнести одиночными
  вызовами.
- **Аудит кейса 6** — `tools/topic_gate_audit.py`: реплей сверки MEMORY.md против реестра,
  печатает кандидатов на переезд и наличие указателей; exit 1 = утечки. Только отчёт.
- **Конфиг** — дефолты `hermes_cli/config_defaults.py`: `memory.topic_gate: false`,
  `memory.topic_registry: ~/.hermes/memories/topics.yaml`; прокинуты через обе точки сборки
  `MemoryStore` (`agent_init`, fallback в `memory_tool`).
- **leak_global** (`controller/topic_memory_shadow.py`) не тронут — верификатор §6 остаётся:
  после включения гейта счётчик обязан замереть по зарегистрированным темам.
- **Реестр тем на машине НЕ создан и конфиг НЕ включён** — это шаг деплоя после приёмки.

## Отклонения от ТЗ на ратификацию

1. **Матчинг правок — строго по old_text** (§5 «старый_текст ищется в store темы»): span
   patch'а без маркера темы не роутится. Ошибся адресом — получишь честную ошибку и повторишь.
   Альтернатива (инферить тему по ПОЛНОЙ записи) отвергнута как магия вне тисков.
2. **Батч с тематической опрандой — отказ целиком**, а не пооперационная маршрутизация:
   сохраняю контракт «nothing was written».
3. **Формат match из примера ТЗ**: `V-O\d+` в моей конвенции нужно писать `re:^V-O\d+`.
   Нагромождать авто-детект регэкспов отказался («прост как слесарные тиски»).
4. **PyYAML недоступен в venv (py3.14)** — реестр читается house-либой `ruamel.yaml` (safe).
5. Указатель в MEMORY.md сознательно exempt от char-limit/drift-гвардов: это ровно та строка,
   которую инвариант §2б держит в основной памяти.
6. Реестр пополняет человек (Вл); заявки от агента — сообщением, без need2write-механики в v0.1.
