# Event-producer v0 + миграция убитых джобов

Ветка `elk/event-producer-v0` (07.11). Статус: пп.1–2 ратифицированы Вл 07.11
вечером и смержены в main (`84057fcd10`). П.3 (маппинг) перерабатывается по
критике Вл: **сущность watch-джоба — постоянное дежурство (следить, анализировать,
перепроверять), а не «статистика по графику»**. Расписание в jobs.json было
механикой крона, а не смыслом работы.

## Правильная модель из джобов

Донорский механизм уже содержал правильный паттерн: `monitor_script` +
`monitor_state.last_output_hash` — дешёвый скрипт-монитор тикает часто и БЕЗ
агента; агентский ход будится только когда хэш выхода изменился (состояние
мира изменилось). Это и есть «дежурство»: непрерывное наблюдение, реакция по
факту события, глубокий анализ после пробуждения.

Классификация работ по сущности:

### Дежурства (standing watches) — следить постоянно, реагировать на изменение
| дежурство | что следить | триггер пробуждения агента |
|---|---|---|
| upstream-watch | донор NousResearch/hermes-agent | изменение дифа upstream vs main → анализ: безопасно ли отставание, гонять ли sync |
| win-runner-recovery-watch | статус Windows-раннера | OFFLINE/зависание → восстановление |
| donor-reports-milestone | накопление донор-отчётов | порог ≥10 новых → сводка по вердиктам |
| hygiene watch (быв. autonomy-tick) | осиротевшие ветки, мусор в репо | находка → разовая задача |

Реализация: systemd-timer с частым тиком вызывает ТОЛЬКО монитор-скрипт
(no_agent); скрипт сравнивает хэш состояния; при изменении — task_emit.py
<event_id> → задача ядра с wait_event будит агента. Агент не ходит по графику
вообще — только по факту изменения.

### Законные синтезы (сырьё копится, дайджест по накоплении)
- weekly-trace-digest (Пн 09:00), self-improvement-watch (Пн 10:00),
  idle-intake-interesting, daily-trace-harvest — это НЕ дежурство, а агрегация
  накопленного сырья. Здесь расписание легитимно; реализация: timer→task_emit
  →wait_event-задача (для no_agent script'ов — просто юнит без агента).

### Категория C — пояснение для Вл
autonomy-tick был «тиком автономии»: каждые 10 минут агент просыпался и делал
обход системы (осиротевшие ветки, рассинхрон, брошенное). Он создан ДО того,
как появились дешёвые скриптовые мониторы, и выполнял их работу агентским
ходом. Его функции распределяются по дежурствам выше (hygiene watch и др.) —
как отдельная сущность не мигрирует.

### Disabled-12 — вперёд не переносятся
Не «в никуда», а: revived по команде Вл как дежурство, если соответствующее
наблюдение снова нужно (пример: france-channel-watch имел правильную структуру
monitor_script+hash).
