# Инцидент 21.11: перезагрузка хоста после GRPO-дымков (swap-теснение)

## Хронология (journalctl -b -1, sar /var/log/sysstat/sa21)
- 03:11-03:12 crash-loop qwen27b-dual (5 падений/рестартов за минуту; ночной, к дневным событиям не относится).
- 12:39:46 я остановил dual под дым; 12:39:50 стартовал grpo-smoke2; из-за моей опечатки пути тот же дым стартовал второй раз (smoke2b, 12:40:25) — двойная загрузка 27B.
- 12:40 sar: memavail 4.8G (с 8.8G), cached 65.8G (18 safetensors-шардов в page cache).
- 12:43,12:49,12:54,13:22 — дымые юниты smoke2b/2c/2d/2e финишировали/падали один за другим (2d,2e — CUDA OOM от фрагментации, 60.4G PyTorch в процессе).
- 13:24:08 :8006 поднят на карту, где ещё жил smoke2e. Аудит 14:2x: это НЕ hermes-gateway-watchdog (тот трогает только свой юнит) и не guard/poll — старт пришёл от второго инстанса hermes (pid 2324850, dev-сессия с пробами qwen27b). Первоначальная атрибуция в этом журнале была неверна — исправлено по journalctl.
- 13:20-13:30 sar -W: pswpin 24/s -> 187/s — система вычитывала swap у живых интерактивных процессов.
- 13:30:04 Вл инициировал перезагрузку; shutdown чистый (90 сек), boot 41 сек. Оом-киллов ядра и hung-task за день 0.

## Причина
Не деградация железа и не OOM-бойня. Пять подряд загрузок/выгрузок 27B- весов (smoke-итерации по 4-5 мин) без управления хост-памятью: page cache забит шардами (65G), ядро для баланс вытеснило в swap спящие интерактивные процессы; к 13:30 рабочий стол Вл жил на 187 страницах/с подкачки. Восприятие = «машина зависла», решение = ребут. Решение человека, а не отказ системы.

## Уроки (по рангам ответственности)
1. Итерация гиперпараметров != отдельный systemd-юнит: полная загрузка весов на каждую пробу — расточительство в 5 раз и источник инцидента. Правильно: один долгий процесс, матрица конфигов внутри.
2. Тяжёлые юниты запускались без -p MemoryMax= — у ядра не было выбора, кроме как давить соседей по всей системе; с лимитом умер бы только мой юнит.
3. Page cache от одноразового чтения весов никто не освобождал (fadvise DONTNEED) — 65G «свободной, но занятой» памяти.
4. watchdog не знает об окне обучения и законно вернул :8006 на занятую карту; взаимного исключения нет.
5. Я не вынес ни одно из этих действий за скоуп согласованного окна и не предупредил — Вл узнал о давлении памяти по поведению рабочего стола.

## Измеримость
sar уже включён (sysstat enabled). Окно любого прогона >=10 мин должно иметь до/после sar -r -W. Порог тревоги до старта: memavail < 25G при намерении грузить >20G.

## Кандидаты в механизмы (ждут «как», по правилу 02.11)
M1 launch-wrapper: MemoryMax + memavail-гейт + fadvise-dontneed после загрузки шардов.
M2 inhibit-флаг окна обучения, watchdog сверяется перед воскрешением dual.
M3 one-process-per-trek: конфигурации матрицей внутри прогона.
